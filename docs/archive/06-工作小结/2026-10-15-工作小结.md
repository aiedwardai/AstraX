## 三、备注：各种坑 & 为什么这么选

**① launchctl 在沙箱被拦（`5: Input/output error`）**
沙箱是非 GUI bootstrap 域，用户级 job「写/提交」系统性不可用（极简对照实验同样 EIO，与 plist 无关）。→ 所有 `launchctl load` 移交用户在真机 Terminal 执行；会话内用 `run_in_background` 临时托管。
**为什么**：沙箱命名空间隔离，连 `ps -p`/`launchctl list` 都枚举不到 launchd 派生进程——验证改以 `lsof`+`curl` 读内核 socket 表为准，别被「ps 抓不到」误导以为进程死了。

**② sudo 被拦（`operation not permitted`）**
内核级 root 调用在沙箱不可达。→ 电源策略 `pmset` 等需 root 的命令如实告知用户本地终端跑，我只做只读核查 + 闭环验证。

**③ 本机无任何包管理器（brew / macports / nix 均无）**
`/opt/homebrew`、`/usr/local/bin/brew` 都不存在。→ 中继原计划 `socat` 走不通，改为**纯 Python stdlib（socket+threading）全双工转发**，零外部依赖。
**为什么**：绕过 brew 安装阻塞；Python 中继可内嵌桥接 IP 自动探测（orbctl/`/etc/hosts`），更可控。

**④ huggingface.co 本环境不可达（HTTP 000）**
→ 改用 `hf-mirror.com`（同一官方命名空间权重，供应链不变）。**为什么**：MTPLX 尊重 `HF_ENDPOINT`，镜像只是传输层绕行，权重哈希同源，不降安全。

**⑤ MTPLX 写死 127.0.0.1，容器连不到回环**
`host.docker.internal` 解析到宿主桥接私有 IP，直连 127.0.0.1/它都够不到仅回环服务。→ 选**方案 E 主机侧中继**（绑 bridge100 私有 IP→转发 127.0.0.1），而非方案 A 改 `--host 0.0.0.0`。
**为什么**：0.0.0.0 监听面变宽需 pf 兜底；中继只在私有桥接 IP 暴露，不在 Wi-Fi/局域网/公网，攻击面更小，MTPLX 零改动。

**⑥ host.docker.internal 解析到 `0.250.250.254`（OrbStack 魔术网关地址，不存在于宿主接口、不可绑）**
实测踩坑。→ 真实可绑桥接 IP 在 `bridge100`（本次 `<ORBSTACK_BRIDGE_IP>`），中继绑它。脚本已内置 orbctl/`/etc/hosts` 自动探测兜底。

**⑦ Open WebUI 0.12 auth 路径变更**
`/api/auth/register` 返回 405，正确是 `POST /api/v1/auths/signup`（首用户自动 admin 并关公开注册）。→ 已建临时管理员 `admin@local.host / ChangeMe#2026`（提醒改密）。

**⑧ 27B 是 Qwen3 带 reasoning，`max_tokens` 太小 content 空**
思考占满 token 预算致正文为空。→ 给足 256+ tokens 即正常。实测定位是 reasoning 占位，非故障。

**⑨ Copilot 已升 v4，旧 Custom OpenAI 路径作废**
新入口 = **BYOK 标签**（免费，本地/自定义端点）；vault 语义检索改由 Miyo 承担，**Self-Host 标签是 license-gated 且非防火墙**。→ 按 BYOK 接 MTPLX（Base=127.0.0.1:8000/v1，Key 必填，Model ID 手填，Enable CORS 兜底）。
**为什么**：保持免费 + 本地优先，避开 Pro/Self-Host license 卡点。

**⑩ Smart Connections 免费核心版自带本地嵌入、零配置**
自定义 MTPLX 嵌入收进 Pro。→ 先跑 3a 默认本地嵌入做「相关笔记」，再决定是否走 3b。组件最少、当天收尾。

**⑪ 进程组 vs 单进程（`| tee` 不适合 launchd）**
`bash mtplx-serve.sh` 派生进程族，`| tee` 在沙箱裂出 toybox tee；单独 kill 服务器会留 pipe 孤儿。→ plist 改 `StandardOutPath`/`StandardErrorPath` 接管日志 + `KeepAlive` + 脚本 exec 单进程。

**⑫ 端口冲突崩溃循环**
我在沙箱 `run_in_background` 的 MTPLX 占着 8000，用户真机 `launchctl load` 后 port in use 崩溃循环。→ TaskStop 我的实例腾端口，launchd 重绑成功（新 PID <N>，30s 采样无重启）。
**为什么记**：切 launchd 前必须先停会话内手动实例。

**⑬ 方案 Y 不启用 Open WebUI vault RAG**
→ 避免与 Smart Connections 形成第二份 vault 嵌入索引 + 同步缺口（OWUI RAG 是 vault 副本索引，不自动监听编辑）。OWUI 回归通用对话台，Copilot 直读活 vault 零同步维护。

**⑭ 方案 C 单实例托管生成+嵌入**
→ 同进程 `/v1/chat/completions` + `/v1/embeddings`，省一个常驻服务、契合 64GB 内存预算（引擎 ~48GB）。

**⑮ 不装 Miyo（选项 A）**
Copilot v4 跨全库语义问答需 Miyo，但用户选组件最少当天收尾。→ Smart Connections 检索 + Copilot 对话/引用笔记，无 Miyo 仍可 `[[笔记名]]` 引用或带入相关笔记。

**⑯ Phase 3 前置纠正：本机未装 Obsidian / Hermes**
实证无 `Obsidian.app`、无 `~/.hermes`。→ 纠正认知：**Obsidian 是桌面 GUI（Electron）非 7×24 守护进程**，真正常驻是 MTPLX 守护 + Hermes 调度；「7×24 第二大脑」= 后端常驻 + 调度常驻，Obsidian 为按需前端。
