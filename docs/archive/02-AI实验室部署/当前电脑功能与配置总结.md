## 二、已搭建的功能栈（核心能力）

### 1. 本地 AI 推理栈 — MTPLX（核心，正在运行）

- 自研 `mtplx` 运行时（受管 Python venv，Python 3.13）
- 对外暴露 **OpenAI 兼容接口**：`http://127.0.0.1:8000/v1`
- 同进程托管两个模型：
  - **Qwen3.8-27B-MTPLX-Optimized-Quality**（文本生成，上下文窗口 256k）
  - **Qwen3-Embedding-4B**（向量嵌入，维度 2560）
- 仅绑定回环地址 `127.0.0.1`，`api-key` 鉴权（落盘 `<MTPLX_STATE_DIR>/api-key`，权限 600）
- **当前状态**：`8000` 端口有 python 进程监听 → 服务在线
- 关键脚本：
  - `mtplx-serve.sh` — 单实例守护启动脚本
  - `verify-mtplx.sh` — 双模型全链路一键验收
  - `mtplx-relay.py` — 纯标准库 TCP 中继（无第三方依赖）

### 2. 对话前端 — OpenWebUI（容器化，当前可能未启动）

- 经 OrbStack 容器运行 OpenWebUI（原规划 `127.0.0.1:3000`）
- 用 `mtplx-relay.py` 让容器穿越回环限制够到 MTPLX；中继只绑 OrbStack 私有桥接 IP，不暴露公网
- **当前状态**：`docker info` 返回失败，监听列表未见 `3000` → Docker/容器当前未运行

### 3. 第二大脑 / 个人 AI 实验室（知识库 + RAG + 自动化调度）

- **数据三级分类**：L1 公开 / L2 内部 / L3 机密；本地优先、派生索引可重建、3-2-1 备份
- **混合协同路由**：本地模型做高频执行，复杂任务脱敏后外派云端 API（DeepSeek-V3/R1 等）
- **Hermes 双 Profile 调度**：Scheduler 每日 08:00 cron 触发「AI Morning Brief」，覆盖 OpenAI / Anthropic / Google AI、猫笔刀微信公众号、LNG 行业新闻等，结果落盘 Markdown
- **Obsidian 笔记库**（Smart Connections / Copilot）原生直连回环地址
- 输出可经 **PPT Master** 渲染为演示文稿

### 4. PDF 摄取管线（`ingest.py`）

- 文本型 PDF 走 PyMuPDF 直抽；扫描 / 无文本层 PDF 走**本地 PaddleOCR（arm64 原生 pip，无容器）**
- 统一产出 `processed/*.md` 规范文本，与知识归属解耦、可全量重建

### 5. 图像 / 视频生成接入方案

- **生图**：Draw Things（原生 macOS + Metal）建议上，复用中继架构不新增暴露
- **生视频**：Wan2.2 5B 能跑但单条 ~2 秒片段约 15 分钟且需与 27B 错峰；14B 变体需 128 GB，本机不可行

### 6. 网络与其他常驻服务

- 代理：**Clash Verge**（监听 `7890`）在运行
- 另有名为 **DeepSeek** 的本地服务监听 `127.0.0.1:50021`（疑似本地推理 / 语音类服务）
- 工作区强制规范（`rule.md`）：任何功能实现前必须**先出架构图 → 再做安全审计 → 后编码**，代码遵循 Google 规范 + 详细中文注释

## 三、关键设计原则

- **单一入口 + 严格回环**：所有本地推理 / 微服务默认只绑 `127.0.0.1`，绝不经 `0.0.0.0` 暴露公网；远程访问（Tailscale）留待后续，当前未开放。
- **读写分离与数据不可变**：模型权重为只读只下资产；个人知识库为 Git 版本化文本；派生的向量索引与缓存可随时全量重建。
- **混合协同路由**：「本地模型做高频执行，云端大模型做复杂思考」，数据依据安全等级本地拦截，坚守数据不出境 / 不上云底线。
- **回退干净**：MTPLX 与中继均支持无残留回退。
